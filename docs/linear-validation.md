## Stepwise decision, 2026-10-23

Stepwise remains an **experimental, opt-in compatibility feature**. The user chose to retain it and defer further work on exact native stepwise parity. Existing APIs, saved models, regression tests and the recorded selection/fallback differences remain supported; this decision does not certify native equivalence or remove stepwise from the long-term GUIDE coverage inventory.

Current effort moves to multiple-linear leaves, split selection and pruning. Stepwise-specific entry/removal rules, flag handling, collinear fallbacks and all-subsets selection are deferred. The multiple-linear numeric small-sample fallback was subsequently resolved in reference7 below; categorical fitting policies are addressed in the subsequent categorical milestone linked above. Revisit stepwise parity when the user reprioritizes it or the active core-validation work requires a concrete shared fix.

## Scope and evidence

Each model family covers complete numerical data, unequal positive weights, numerical missingness, an entirely missing predictor, collinear predictors, a small sample and moderate signals. A further stepwise case limits selection to one variable while both candidate F probabilities underflow. Features have fit-only roles, so these cases isolate leaf fitting and selection. Native settings explicitly include an intercept, no prediction truncation, no pruning, depth one and minimum node size two.

`tools/capture_reference_linear.py` follows templates generated by GUIDE 46.3's interactive writer. Captures retain the batch, DSC/data/CSV, full options and dataset, report, split encoding, prediction table, coefficient/selected-variable file, generated R, stdout/stderr, executable hash and hashes of every retained artifact. Existing output paths cannot be overwritten. Failed runs become incomplete diagnostics.

The parser requires the requested runtime banner, final root-only tree, effective depth/minimum size, model type, stepwise alpha/variable limit, no truncation and completion evidence. It cross-checks coefficients and selected variables against the generated native R output, then independently evaluates those exported coefficients at every input row and compares with the separate native prediction table. Generated native R is retained as output evidence; neither the capture parser nor the Rust runtime executes it.

Native exported coefficients have about 12 significant digits; Rust comparisons use `2e-9 * (1 + abs(coefficient))`. Prediction tolerances are half the last printed unit plus `1e-9`, derived from each native token. Rust centered/scaled coefficients are converted to original predictor units before comparison. For collinear multiple regression, tests compare the identifiable combination `beta_x + 2*beta_z`, rather than requiring identical QR pivots. This establishes fitted predictions on that design, not predictions away from its column span. Saved-model round trips preserve every Rust prediction.

An independent R `lm` check covers all 15 datasets with weighted-mean imputation and the columns selected by Rust. It verifies leaf estimation for the historical cases below; it does **not** certify the variable-selection algorithm. Runtime fitting remains pure Rust.

## Corrected F-tail failure

The 3,200-row orthogonal design has response `x + 1.1*z + 0.01*noise`, with balanced independent sign columns. Both univariate ordinary F probabilities round to zero. With a one-variable limit, Rust previously selected whichever predictor appeared first. A regression test reproduced selection of the weaker `x` before the correction.

Stepwise entry and removal now compare log F tails. The F statistic is formed in log space from residual risks and effective degrees of freedom, avoiding intermediate ratio overflow. Bonferroni entry thresholds also remain in log space. Both column orders now select `z`, matching both pinned native executables. New models/reports record **`guide-rs-0.1-experimental-reference5`**; saved-model format remains 1.

New `stats::beta_log_regularized` and `stats::f_log_survival` functions retain extreme probabilities. The F-to-beta transformation avoids overflow of `numerator_df * F`. An independent R `pf(..., lower.tail=FALSE, log.p=TRUE)` comparison covers 54 values across six degree-of-freedom pairs, including ordinary underflow, degrees of freedom 100,000 and finite F values up to `f64::MAX`. An analytic F(2,2) identity checks `log(survival) = -log1p(F)` independently.

### Numerical rank-bound correction

Missing split rows exposed a Rust error at node 5: Rust selected `x=61.5` by counting missing rows toward the candidate's child-size requirement. That left only two observed split values on one side. Native selected `x=49.5`, with seventeen and thirteen observed values before missing-row routing. Independent weighted/unweighted least-squares enumeration confirmed that the native cut minimizes the objective over its admissible observed ranks.

Numerical threshold candidates now use observed row ranks, including repeated values, before routing missing observations. GUIDE's endpoint convention is asymmetric: `left_observed >= min_samples_leaf` and `right_observed > min_samples_leaf`. Additional local forward/reversed boundary probes under both pinned versions confirmed this convention with minimum sizes two and twelve. A four-row/minimum-two native control has no split. Missingness-only splits remain separate candidates and use total child counts; categorical, periodic and projected split constraints have not been changed.

Portable regression tests first reproduced the invalid missing-row cut and then verify the correction and asymmetric endpoints. Two four-row CLI/export smoke tests now explicitly use minimum one to retain their intended two-leaf setup. New models/reports record **`guide-rs-0.1-experimental-reference6`**; saved-model format remains 1. Previously saved cuts/routes are preserved on load.

## Numeric fallback policy and prediction truncation, 2026-10-24

Forty-seven new cases per native version add **94 captures**, bringing the fixed corpus to **244 captures across 122 distinct cases**. Both pinned native versions agree on all new parsed results. Earlier captures remain unchanged, including the historical `small_multiple_fallback` label: its predictions now agree with Rust. One higher-dimensional native least-squares counterexample is preserved as an explicit correctness difference, described below.

### Verified fallback thresholds

For `NodeModel::Linear` with squared-error loss and numerical fitting columns only, define:

- `p`: the number of declared numeric `fit`/`both` columns, including constant and collinear columns.
- `m`: the number of those columns with missing values anywhere in the input dataset. Missing flags are global structural metadata, including rows excluded for missing responses or zero weights.
- `n`: the number of active rows in the current node or CV training fold; positive weight magnitudes do not multiply this count.

Rust now fits a constant when `n < p + 7` if `m=0`, or when `n < p + m + 3` otherwise. At the threshold, weighted QR fitting proceeds using estimable terms; a constant remains possible when no term is estimable or the solver cannot produce a fit. The threshold uses nominal columns/flags, independently of effective QR rank. At this numeric milestone, categorical and periodic fitting designs retained the existing rank-aware fallback. The subsequent categorical milestone extends the verified guard to mixed categorical/numeric designs; periodic policies remain unverified. These are fitting thresholds on accepted designs, not a claim of identical native input rejection for every tiny or invalid nominal dimension.

The 32 boundary cases cover both sides of the threshold with 1, 2, 3, 4 and 7 declared predictors, constant/collinear designs, ordinary weights, zero weights, missing regressors, entirely missing regressors, and missing values in excluded rows. A further two-leaf case proves that a global flag affects the threshold in a child that has no local missing values. This resolves the earlier four-row/two-predictor discrepancy: both implementations now return 2.95 on a new fit.

### Prediction limits

`FitOptions.prediction_truncation` supports four wire values for multiple-linear squared-error leaves:

| Value | Limits |
|---|---|
| `none` | Unbounded prediction; the Rust default for compatibility |
| `node_range` | Minimum/maximum response among the leaf's active training rows |
| `node_range_expanded` | Node range padded at each end by 10% of its width |
| `global_range` | Full active training response range; GUIDE's native default |

The global range excludes missing responses and zero-weight rows. As in GUIDE, global limits are fixed from the full active training sample across CV folds; node limits are recalculated within each fold. Thus global limits are a full-training choice, not a fold-local estimate. Native/Rust LOOCV fixtures check both conventions. Other losses/node-model families reject non-default truncation settings explicitly.

Fitting coefficients, residual signs used in variable selection, training search risks and weakest-link risks remain untruncated. Returned predictions, including predictions at training rows, and held-out losses use the chosen limits. Fixed-size fixtures compare the unchanged untruncated alpha path between `none` and `node_range`. A quadratic example independently checks raw training risk 877.8 while bounded predictions replace negative fitted values with zero.

The fourteen limit cases cover root and two-leaf models under every mode, out-of-range and missing predictor values, missing-response prediction rows, a zero-weight response outlier, two LOOCV modes, training clipping and fixed-size pruning. For the two-leaf example, out-of-range predictions `(203, -97)` become `(49, 103)` with node limits, `(53.6, 98.4)` with expanded node limits, or `(149, 3)` with global limits.

Finite bounds are serialized in each linear model's optional `prediction_bounds` field. Older JSON without either new field remains unbounded and loads without refitting. A regression test restores the old four-row linear model and preserves its original plane/extrapolation, even though refitting now chooses a constant. Invalid/inconsistent bounds are rejected. Bounded models require a reader that understands the new fields; compatibility here means the new reader loading older JSON. New fits/reports record **`guide-rs-0.1-experimental-reference7`**; saved-model format remains 1.

See [`examples/linear-limits.json`](../examples/linear-limits.json) for a CLI configuration. No R prediction export is generated by the new capture tools or implemented for these features. The independent R oracle uses weighted QR and direct numerical predictions only.

### Native least-squares counterexample

`linear-policy-two-missing-p4-n9` has nine active observations, four numerical fitting columns and two generated missing flags. The native fitter proceeds at the verified threshold, but its fitted predictions are not a least-squares optimum:

| Quantity | Native 46.2/46.3 | Independent R QR / Rust |
|---|---:|---:|
| Training sum of squared errors | 3.25 | 2.70 |
| Sum of residuals where `x1` is missing | −0.5 | Approximately zero |

That residual sum is the normal equation for the `x1.NA` indicator; a nonzero value disproves unconstrained least-squares optimality for this design. Rust retains the independently verified QR fit. This is a fitting correctness difference, separate from the earlier CV scan defect, and does not change the fallback threshold.

[`diagnostics/native-qr-difference.json`](../tests/fixtures/linear-policy/diagnostics/native-qr-difference.json) pins native manifests/binaries, input files and the independent R script, and preserves both prediction vectors, objectives and every normal-equation residual. Regular tests verify both native results and the correct fit explicitly; Python recomputes the diagnostics. The R interoperability suite independently regenerates the correct predictions for all 47 datasets. No source of the native numerical failure is claimed.
